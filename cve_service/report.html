CVE-2009-1390 MEDIUM APPLICABLE
No validator available 		Mutt 1.5.19, when linked against (1) OpenSSL (mutt_ssl.c) or (2) GnuTLS (mutt_ssl_gnutls.c), allows connections when only one TLS certificate in the chain is accepted instead of verifying the entire chain, which allows remote attackers to spoof trusted servers via a man-in-the-middle attack.

Mitigation Steps:

  1. Update Mutt to version 1.5.20 or newer to apply the official fix for certificate chain validation.
  2. Ensure Mutt's configuration explicitly sets `ssl_verify_host = yes` and `ssl_verify_certificates = yes` in `.muttrc`.
  3. Regularly review and update the system's trusted Certificate Authority (CA) bundles to prevent acceptance of compromised certificates.
  4. If immediate update is not possible, restrict Mutt's use to trusted internal networks or a secure VPN connection.
CVE-2009-3765 MEDIUM APPLICABLE
No validator available 		mutt_ssl.c in mutt 1.5.19 and 1.5.20, when OpenSSL is used, does not properly handle a '\0' character in a domain name in the subject's Common Name (CN) field of an X.509 certificate, which allows man-in-the-middle attackers to spoof arbitrary SSL servers via a crafted certificate issued by a legitimate Certification Authority, a related issue to CVE-2009-2408.

Mitigation Steps:

  1. Upgrade Mutt to a version beyond 1.5.20 to apply the necessary certificate validation fixes.
  2. Configure all mail clients, including Mutt, to enforce strict hostname validation and certificate pinning.
  3. Educate users to never bypass certificate warnings and always verify certificate details before proceeding.
  4. Review and ensure all mail server certificates are correctly formed, without NULL characters in the Common Name (CN) field.
CVE-2009-3766 MEDIUM APPLICABLE
No validator available 		mutt_ssl.c in mutt 1.5.16 and other versions before 1.5.19, when OpenSSL is used, does not verify the domain name in the subject's Common Name (CN) field of an X.509 certificate, which allows man-in-the-middle attackers to spoof SSL servers via an arbitrary valid certificate.

Mitigation Steps:

  1. Update Mutt to version 1.5.19 or later to apply the fix for X.509 certificate Common Name (CN) verification.
  2. Restrict mutt usage to trusted, known mail servers by configuring strict firewall rules or network segmentation.
  3. As a temporary measure, use an alternative, fully patched email client for sensitive communications.

CVE-2007-3205 MEDIUM APPLICABLE
No validator available 		The parse_str function in (1) PHP, (2) Hardened-PHP, and (3) Suhosin, when called without a second parameter, might allow remote attackers to overwrite arbitrary variables by specifying variable names and values in the string to be parsed. NOTE: it is not clear whether this is a design limitation of the function or a bug in PHP, although it is likely to be regarded as a bug in Hardened-PHP and Suhosin.

Mitigation Steps:

  1. Update PHP to the latest stable and patched version available.
  2. Review all application code and modify `parse_str()` calls to always use the second parameter (e.g., `parse_str($string, $array)`).
  3. Implement strict input validation on all user-supplied data before it is passed to `parse_str()`.
  4. Deploy or configure a Web Application Firewall (WAF) to detect and block requests attempting variable overwrites.

  1. Update the PHP Radius extension to version 1.2.7 or higher immediately.
