═══════════════════════════════════════════════════════════════
SCAN STRATEGY — TWO-PHASE APPROACH
═══════════════════════════════════════════════════════════════

Never guess what service runs on a port. Always probe actively with -sV.

PHASE 1 — PORT DISCOVERY (fast sweep):
  nmap -T4 --top-ports 1000 --open <target>

  This finds open ports quickly without deep probing.
  -T4 = aggressive timing (fast, reliable on LAN/local)
  --top-ports 1000 = scan the 1000 most common ports
  --open = only show open ports (cleaner output)

  Parse the result to identify which ports are open. Then proceed to Phase 2.

PHASE 2 — SERVICE/VERSION PROBING (targeted):
  nmap -sV -sC -p<open_ports_comma_separated> <target>

  Example: if Phase 1 found ports 22, 80, 443, 31337 open:
    nmap -sV -sC -p22,80,443,31337 <target>

  -sV = probe open ports to determine service/version info (THIS IS THE KEY FLAG)
  -sC = run default NSE scripts (safe scripts only, adds vulnerability context)
  -p<ports> = only probe the ports that were actually found open in Phase 1

  This is fast because you're only probing the handful of ports that are open,
  not all 1000. This is how you identify that port 31337 is actually HTTP,
  or that port 10010 is running an SSH service.

═══════════════════════════════════════════════════════════════
SHORTCUTS — SKIP PHASE 1 WHEN:
═══════════════════════════════════════════════════════════════

- User specifies exact ports: "scan port 8080 on X"
  → nmap -sV -sC -p8080 <target>

- User asks for a specific check: "check SSH on X"
  → nmap -sV -sC -p22 <target>

- User asks for a quick/stealth scan: "quick scan X"
  → nmap -T4 -F --open <target>  (top 100 ports, no -sV yet)

- User asks for help/info:
  → nmap --help

═══════════════════════════════════════════════════════════════
ADVANCED SCANS — ONLY WHEN EXPLICITLY REQUESTED
═══════════════════════════════════════════════════════════════

OS detection:     nmap -O -sV <target>
  Requires root/sudo. Only use when user asks "what OS" or "full scan".
  Often needs sudo — the tool handles this automatically.

UDP scan:         nmap -sU --top-ports 50 <target>
  Slow. Only when user explicitly asks for UDP.
  Limit to --top-ports 50 to avoid timeout.

Vuln scripts:     nmap --script vuln -p<ports> <target>
  Only AFTER Phase 2 identified services. Targets specific ports.
  Can be slow — use --script-timeout 30s if needed.

Full comprehensive: nmap -sS -sV -sC -O --top-ports 1000 <target>
  Only when user says "full scan" or "comprehensive".
  Requires root. May hit the 120s timeout on large networks.

═══════════════════════════════════════════════════════════════
NETWORK SCANS — SUBNETS/RANGES
═══════════════════════════════════════════════════════════════

Host discovery:   nmap -sn <subnet>  (e.g. 192.168.1.0/24)
  Ping sweep only — no port scanning. Finds live hosts.

Web server hunt:  nmap -p80,443,8080,8443 --open -T4 <subnet>
  Fast sweep for web services across a network.

═══════════════════════════════════════════════════════════════
TIMING GUIDANCE
═══════════════════════════════════════════════════════════════

-T1   Very slow, IDS evasion. Rarely needed.
-T2   Polite, slow. For fragile networks.
-T3   Default. Good for most cases.
-T4   Aggressive, fast. BEST for LAN/local testing. (PREFERRED)
-T5   Insane speed. Unreliable on WAN. Avoid.

Always prefer -T4 for local/LAN scanning. Use -T3 for unknown/remote targets.

═══════════════════════════════════════════════════════════════
TIMEOUT AWARENESS
═══════════════════════════════════════════════════════════════

The tool has a 120-second timeout. If a scan times out:
1. Reduce scope: fewer ports (--top-ports 100 instead of 1000)
2. Use faster timing: -T4 or -T5
3. Drop -sC (NSE scripts are slow)
4. Scan ports individually or in small groups
